# DataX MCP

把 DataX 同步任务做成可通过 MCP 操作的工具。Go 管任务和断点，DataX 的 Java 进程负责真正搬运数据。关闭对话或 MCP 客户端，不会丢掉已排队任务；独立工作进程继续运行。

## 第一版范围

- MySQL → PostgreSQL，显式选择字段和整数 ID 范围。
- 分批全量、按 ID 追加增量、暂停和恢复。
- 每批先写暂存表，再在一个事务中合并、比较、写完成记录。
- 密码由工作进程环境提供，不作为 MCP 参数传入。
- 本地单机运行，不提供集群调度；Linux/macOS，Go 1.26，Java 8。

[MCP 配置与启动步骤](../README.md#start-here)包含完整示例。先在独立目标表验证小批数据，再扩大范围。`chunk_size` 是 ID 区间宽度，不是固定行数；上界需要操作者确认。

## 正确理解断点

每一批完成目标库事务后才保存本地断点。如果目标已经提交、本地断点还没写入就断电，恢复时查询目标完成记录，避免重复搬运。已经完成的批次不会因后续失败被推倒重来。

“校验行数”表示暂存表与最终目标一致，不代表已经独立核对源库。实际源字段是否保真，仍需小批验证。测试已覆盖中文、表情、零字符、空值/空串、超大 ID；时间与小数通过显式文本投影保留精度。

## 尚不支持

按 ID 追加不会发现旧记录修改、删除或迟提交记录。全量重跑可以刷新字段，但不会删除源端已消失的数据。没有 CDC、多表一致快照、自动字段推断、SSH 隧道管理、业务筛选与定时调度。业务项目需要自行定义这些要求，不能因为包装了 MCP 就默认它们成立。
